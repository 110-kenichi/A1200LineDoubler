# v0.30wip 配線レビューと RTL シミュレーション（2026-09-29）

対象：`hardware/amiga_scandoubler_v030wip.kicad_pcb`（コミット 449b58d）。数値の区別は次のとおり。
- 実測：基板の形状から計算した値、またはシミュレーションの結果。
- 推定：遅延係数やデータシートの値を仮定した計算。

## 1. RTL シミュレーション（実測）

- 環境：Icarus Verilog 12.0（apt）。mapped_reset のセルモデルは YoWASP Yosys 同梱の Gowin `cells_sim.v`。
- 実行した `sim/run_*.py`：12本すべて。
- 結果：**全 PASS（PASS 82件、失敗0件）**。ログは `work/v031dac/sim/`。
  - line_double（N=32/1816/1820/2048）
  - field_sync（524–626 ライン）
  - capture 24件、stream 8件、video 6件、control 17件、ADC boot 4件、PLL restart 3件、clock 2件
  - output stage、board startup、system、mapped_reset（2/32/65）
- 範囲の限界（テスト自身の注記どおり）：
  - ベンダーの PLL/ODDR の実モデル、実機の GSR、基板の遅延は含まない。
  - ピン割当はシミュレーションに関係しない（RTL は不変）。

## 2. 基板を含むタイミング（推定）

- 配線の遅延係数は 5.8–7.2 ps/mm と仮定した（外層マイクロストリップ）。
- **DAC**：
  - データ線は 29.6–48.9mm。クロック経路（DAC_CLK_RAW + BUF + DAC_CLK）は 32.5mm。
  - 基板の差 X_board = −21…+118 ps。
  - `dac_timing_budget_v031.json` の要求（U6 の 15/50pF の遅延範囲を含む）に入れると、未知の「データのパッド遅延 − クロックの ODDR/パッド遅延」の許容範囲は −3.05〜+6.11 ns になる。
    - 最も厳しいピン：setup 側は R7（2048 条件）、hold 側は B1（1816 条件）。
  - 同種の OBUF どうしの差としては十分に広い。ただし、パッド遅延が SDF にないため確定ではない。
- **ADC**：
  - データ線は 12.7–48.7mm（HS/VS が最長）、ADC_CLK は 28.3mm。
  - 基板上のずれは −0.11…+0.15 ns で、取り込み余裕 +4.285 ns（推定）に比べて小さい。

## 3. 配線の検査（実測、`scratch rev/*.py` による形状計算）

### 3.1 クロック
| ネット | 長さ | ビア | 基準面の切れ目（ビア周り以外） |
|---|---|---|---|
| ADC_CLK | 28.3mm（B.Cu 26.0） | 2 | 0.18mm |
| REF_27M | 31.0mm | 4 | 1.14mm（U1 上辺の近く） |
| DAC_CLK_RAW / BUF / DAC_CLK | 20.7 / 5.0 / 6.8mm | 0 | 0 |

- B.Cu の基準面は In2（3V3 面）で、GND には直接隣接していない。
- ADC_CLK と REF_27M は B.Cu が大部分。リターン電流は 3V3 面とパスコンを経由する。
  - 28MHz 程度なら大きな問題になりにくいと考えるが、評価はしていない。

### 3.2 アナログ入力（Amiga から、使用する入力）
| ネット | 長さ | ビア | 切れ目 |
|---|---|---|---|
| RIN_1 | 12.1mm | 2 | 0 |
| GIN_1 | 20.1mm | 2 | **4.9mm**（(14–17.6, 41.6–43.6)。In2 の ADC_1V9A/ADC_3V3A の線をまたぐ） |
| BIN_1 | 9.9mm | 2 | 0 |
| R_IN/G_IN/B_IN（75Ω 終端の前） | 10.0 / 12.4 / 16.3mm | 0 | 0 |

### 3.3 パスコンの距離（IC の電源ピン → 同じネットの最寄りのパスコン、直線距離）
- **U2.12（3V3）11.6mm、U2.23（3V3）9.3mm**：近くにパスコンがない。
  - 課題5・6で C37 と C35 を移動した結果である。**要対策**。
- U2.78 5.0mm、U6.5 4.8mm、U5.5 4.5mm、U2.58 4.4mm：やや遠い。
- 残りの 27ピンは 4mm 以内。

### 3.4 そのほか
- 基準面の切れ目を 1mm 以上またぐもの：
  - POWER_GOOD（5.4mm）と FPGA_DONE（5.3mm）は静的な信号なので問題ない。
  - ADC_HS/VS（約3.2mm、同期信号）、H_OUT_RAW（1.6mm）、B/G_OUT（1–1.6mm、U3 の右で DAC_3V3 の In2 線をまたぐ）、I2C_SDA、DAC_PSAVE_N、ADC_RESET_N、REF_27M。
- DAC 出力 R/G/B_OUT：22.0 / 27.0 / 29.3mm、各ビア2個。

## 4. 指摘と対策案

| # | 重要度 | 内容 | 対策案 |
|---|---|---|---|
| 1 | 高 | U2 の 3V3（VCCO）pin12・pin23 の近くにパスコンがない（11.6 / 9.3mm） | pin12 は右辺の階段状ビアの北、pin23 は右上角の空きに 0402 の 100nF を追加し、面ビアで接続する（部品を追加する場合は回路図の変更が必要） |
| 2 | 中 | GIN_1 が In2 の電源線の上を 4.9mm またぐ | In2 の ADC_1V9A/ADC_3V3A 線を GIN_1 の下から外す、または GIN_1 を F.Cu に寄せる |
| 3 | 中 | クロック（ADC_CLK、REF_27M）の大部分が B.Cu で、基準が 3V3 面 | ビアの近くに GND のステッチビアを追加する。本格的な変更は大きいので保留 |
| 4 | 低 | B/G_OUT（DAC のアナログ出力）が U3 の右で DAC_3V3 の In2 線をまたぐ（約 1mm） | 必要なら In2 線を少し移す |
| 5 | 低 | U2.78、U6.5、U5.5、U2.58 のパスコンが 4.4–5mm | 現状維持でもよい。余裕があれば寄せる |
