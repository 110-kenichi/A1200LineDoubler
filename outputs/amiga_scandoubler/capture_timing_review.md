# 画素のクロック間受け渡し調査 v0.16

2026-09-12。前版のFPGA配置配線を同じ手順で再実行し、配線遅延SDFを出力した。RGB24bit・HS1bit・更新トークン1bit、計26経路を両プロファイルで抽出した。今回、現行90度設定の余裕不足が疑われる条件と、出力された遅延モデルの欠落が見つかった。

## 暫定計算

以下は28.375MHz、PLL出力2倍・90度を理想とした推定。単位ns。残りはPLL位相誤差・ジッター等をまだ差し引いていない値で、setup slackの保証値ではない。

|サンプル数|必要な理想エッジ間隔の推定最大|ADC High 50%で残る時間|ADC High 52%で残る時間|
|---:|---:|---:|---:|
|1816|3.358|1.047|0.342|
|2048|3.837|0.568|-0.137|

90度は2倍クロック自身の周期に対する角度。入力周期Tとして、ADC立ち下がりから次の映像立ち上がりまでは `(0.625 − ADCのHigh比率) × T`。28.375MHzでHigh 50%なら4.405ns、52%なら3.700nsとなる。

必要時間は「送信FFのclock-to-Q＋データ配線＋途中LUT＋受信FFのsetup＋送信側クロック配線−受信側クロック配線」で見積もった。ADC側と映像側のクロック到着時刻の差を無視しない。PLL内部の位相関係・入力経路・ジッター、クロック不確かさ、最小遅延側のholdはこの式で検証し終えていない。

2048条件のHigh 52%では暫定値が約−0.137ns。これは実機違反の確定ではないが、現在の90度設定を完成設定として承認できる結果ではない。前版の単一クロック領域Fmaxの合格とは両立する問題である。

## 遅延モデルの欠落

配置後、取得FFと受信FFの間にpassthrough LUTが挿入されている。これは [使用版nextpnrのcreate_passthrough_luts処理](https://github.com/YosysHQ/nextpnr/blob/a601751d/himbaechel/uarch/gowin/gowin.cc) と一致する。しかし、26経路すべてで挿入LUTのI3→F遅延がSDFに記載されていなかった。

欠落を0として合格にせず、同じSDF内の他のLUT4 I3→F遅延最大値625psを参考値として補った。そのため上表は推定であり、その625psが挿入LUTの実遅延を保証するとは言えない。生のSDF、欠落数、各経路の内訳を残した。モデルのmin/typ/maxが同値になっている配線もあり、PVTを含む包括的な最悪条件解析ではない。

## 180度候補

180度へ変更すると、理想的には `(0.75 − ADCのHigh比率) × T` に受け渡し時間を広げられる。28.375MHz・High 52%なら8.106ns。現行の配置遅延が同じと仮定した場合、2048条件の差引きは約4.269nsになる。位相変更後の実装結果ではない。

入力取り込み試験に位相指定を追加し、90度と180度をそれぞれ4周期×3デューティー×2データ遅延の24条件で試験した。各5,472画素、合計10,944画素のRGB/HSの整合・連続性・sample_ce・リセット復帰が通過した。試験は理想クロックを用いる機能試験であり、メーカーPLLや配線遅延を反映した試験ではない。

**製品側RTLのPLL設定はまだ90度のまま。180度は次に実装・検証する候補であり、変更済みとは扱わない。** 変更時は実PLL設定、ADCから映像へのsetup/hold、入力RGB/HSの取得、DACクロックとの関係、VS位置を含む全体接続を再確認する。

## 再現と記録

`implementation/capture_1816.sdf`、`capture_2048.sdf` と各route.logを同梱。生成は前版の `implementation/commands.txt` のコマンドへ `--sdf implementation/capture_<サンプル数>.sdf` を追加して行う。配置済みJSONの再読み込みではツール内部assertionが起きたため、元の合成JSONから同じ条件で配置配線を再実行した。

```text
python implementation/analyze_capture_sdf.py
python sim/run_capture_tests.py --bin-dir <Icarusのbinフォルダー> --phase 90 --report capture_phase90_report.txt
python sim/run_capture_tests.py --bin-dir <Icarusのbinフォルダー> --phase 180 --report capture_phase180_report.txt
```

`capture_timing_estimate.json` に52経路の内訳、SDFハッシュ、理想エッジ間隔、欠落モデルの補完値を保存した。解析スクリプトは経路数・送受信エッジ・クロックの出所を検査してから計算する。

プリント基板は95×95mmの未配線案。今回の調査は、基板配線と製造データを固める前に解決すべきタイミング課題を特定するもの。Gerber・完成BOM/CPL・実機ビットストリームは未完成。
