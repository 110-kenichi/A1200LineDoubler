# 出力リセット解除の同期化 v0.20

2026-09-13。出力段の近くに2段の解除用レジスタを追加した。表示許可が戻ったとき、27本の出力レジスタを長い表示許可の組合せ経路から直接解除せず、映像クロックに同期したローカル信号で解除する。

## 動作

電源・クロック監視の不許可またはresetで、解除用2段を非同期に1へ戻し、RGB/BLANKを0、H/Vを1にする。許可が戻ると、映像クロックの最初の2立上りでは出力を保持し、3回目から有効入力を取り込む。クロックが停止したままなら解除しない。

通常表示の1クロックの出力段遅延は前版と同じ。追加待ち時間は起動・復帰時だけであり、毎画素に2クロック追加するものではない。PSAVEは従来の独立監視経路のまま。追加部品なし。

初期値は解除用2段=11、RGB/BLANK=0、H/V=1。合成後に2個のDFFPが直列接続され、その出力が27本の非同期クリア／プリセット端子を駆動し、各出力FFからOBUFへ直接接続することを確認した。プリミティブ既定INITも照合した。実デバイスのコンフィギュレーション中・GSR動作は引き続き別確認。

## 試験と配置結果

RTL単体と合成後単体は各593件PASS。従来の画素・BLANK・同期の整列に加え、1周期内の17種類の解除時刻、最初の2立上りの保持、クロック停止中の解除禁止と復帰を照合した。デジタル論理シミュレーションであり、メタステーブル挙動やアナログ的な解除規格の検証ではない。

全体試験は12,261回の可視RGB照合、ADC設定、停止復帰、電源断、NACK時消灯をPASS。2プロファイルとも再合成・配置配線を完了した。

解除側の数値は、最終解除FFのclock-to-Q、クロック配線差、27出力FFのCLEAR/PRESETまでの配線をSDFから抽出した値。**SDFにrecovery/removal規格が27本とも存在しないため、上記は解除タイミングの最終slackではない。** ジッター、全PVT、最初の同期段の動作も保証しない。次の立上り前のrecoveryに加え、同じ立上り後のremoval条件も必要であり、後者を省略して合格とはしない。

DACデータ側の最大抽出遅延は両条件とも3.632ns。出力FFからOBUF入力までで、OBUF、ODDR、基板、負荷を含まない。ADC側の26経路も再抽出し、High52%時の暫定予算は1816で3.786ns、2048で4.269ns。1816は再配置によって前版より0.483ns減少した。欠落LUTを借用値で補う推定条件は同じ。

## 再現・成果物

現行は `implementation/output_release/`。`commands.txt` に合成、配置配線、接続検査、3種類の経路解析、単体・全体試験の手順を記載した。`release_timing.json` に27経路×2条件の結果とSDFハッシュ、`analyze_release.py` に抽出処理を保存した。

旧 `output_stage/` はv0.19、旧 `phase180/` はv0.17の実装履歴。現在のRTLをそれらの配置結果と組み合わせない。更新された単体テストは2段の解除待ちを前提とするため、旧単体ネットリストに対する再現には旧版ZIPのテストを使う。
