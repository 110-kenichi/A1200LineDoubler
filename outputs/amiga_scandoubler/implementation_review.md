# FPGA配置配線の試行 v0.15

2026-09-12。GW1N-LV4QN88C6/I5を指定して、基板用トップの配置配線が1816/2048サンプル条件で完了した。RTL・回路図・基板はv0.14から変更していない。これはFPGA内部の配置配線であり、プリント基板は未配線のまま。

## 結果

|1ラインのサンプル数|配置後LUT4|FF|BSRAM|映像クロックの単一領域Fmax MHz|
|---:|---:|---:|---:|---:|
|1816|1106|672|6|80.37|
|2048|1120|674|6|92.29|

BSRAMは10個中6個。PLLは `X27Y0/PLL`、DACクロックのODDRは `X0Y16/IOLOGICBO`、同じ端子の出力バッファは `X0Y16/IOBB` に配置された。これは端子16へ変更した構成でのツール上の配置結果であり、実機動作の確認ではない。

上表のFmaxは映像クロック領域内のレジスター間の値。ADCから映像クロックへの受け渡しやDACとの入出力タイミングを含む「全体動作可能周波数」ではない。パッキング直後と配置後では、共有されたセルの集計が異なる。IOBの available=218 はデバイス内資源の表示であり、QN88の使用可能端子数を意味しない。

## 使用環境と再現

[OSS CAD Suite](https://github.com/YosysHQ/oss-cad-suite-build/releases/tag/2026-09-12) Windows x64版、nextpnr-0.11.1-26-ga601751dを使用。配布元のSHA-256とアーカイブの一致を確認した。配置配線ツール、GW1N-4データベース、付属ランタイムを使用した。[Gowin向けnextpnr手順](https://github.com/YosysHQ/apicula/wiki/Nextpnr%E2%80%90Himbaechel-Gowin) に従ってデバイス・family・CSTを指定した。

展開したamiga_scandoublerを作業ディレクトリーにし、OSS CAD Suiteの実行環境を有効にして `implementation/commands.txt` のコマンドを実行する。`sspi_as_gpio` を指定している。ツール本体は配布一式に含めていない。

`implementation/` にログ、配置配線後JSON、タイミングレポート、実行コマンド、入力合成データのハッシュ、集計を同梱した。JSONはビットストリームではない。

## 周期指定の修正

最初は入力端子に27MHz/28.375MHzの周期を指定したが、パッキング後のレポートでは内部クロックが一律56.75MHzとなっていた。この結果を所定の周期での検証とは扱わず、入力バッファ後の実在するネットへ周期を指定して再実行した。

同梱版では、レポートにREF=約27MHz、ADC=約28.375MHz、VIDEO=約56.75MHzが反映されていることを照合済み。ツールの時間分解能による丸めを含む。使用した `exploratory_periods.sdc` は周期だけの試行用制約で、ADC/VIDEOの位相関係、クロック不確かさ、外部setup/hold、基板遅延を規定していない。

## 残る警告と検証範囲

各実行に、ADCデータ `logic_core.adc_rgb[6]` の専用経路による配線に失敗したという警告が1件ある。その後の通常配線処理は完了し、実行結果は0 errors。警告を削除せずログと集計に残した。これはADCデータ経路の実機タイミングを保証するものではない。

クロック間の遅延の表示は配置前の見積りにも存在するが、最終レポートのcritical_pathsは各単一クロック領域の3本のみ。ADC負エッジからVIDEO正エッジまでの短い位相窓について、配線後の保証が得られたとは言えない。合格表示だけでその受け渡しを承認しない。

次に必要なのはADC/VIDEO間の位相と配線遅延、外部RGB・HS入力、DAC RGB/BLANK/クロックのsetup/hold、実GSR初期化、設定兼用端子の解放条件の確認。実入力プロファイルと長短ラインの連続処理も未完成。プリント基板の配線・DRC・Gerber・完成BOM/CPL・実機ビットストリームは引き続き未完成である。
