## 追記（2026-09-30）JLCPCB の DFM と発注画面への対応

利用者が JLCPCB の DFM（PCB DFM）と部品の画面で確認した結果への対応。基板を変更した。

### DFM の赤の項目と対応

| DFM の項目 | 原因（基板データで特定） | 対応 |
|---|---|---|
| Pad spacing（表面 赤10） | パッドと同じネットのビアの間隔 0.05〜0.063mm（C11/C18/C34/C43/C46/C5/C54、FB1〜FB4）。JLC はビアのランドもパッドとして数える | ビアを動かした（下記） |
| Via to pad（赤1） | U2.67 と 3V3 ビア (45.6, 47.6)。穴の縁からパッドまで 0.114mm | ビアを動かした |
| Annular ring（赤1・橙98） | 0.5/0.3mm の GND ビア (17.15, 46.45) のリング 0.10mm。橙は 0.55/0.3mm のビア（0.125mm） | 0.55mm に広げると U1.22 と ADC_1V9A の配線とのクリアランスが足りない（0.175mm）ので **そのまま**。JLC の製造能力の範囲内 |
| Slot width（赤4） | J3 の固定用の長穴4個、幅 0.6mm | **幅 0.8mm・パッド 1.2mm に広げた**（JLC/EasyEDA の C165948 のフットプリントと同じ幅）。新フットプリント `Amiga.pretty/USB_C_Receptacle_HRO_TYPE-C-31-M-12_Slot0.8.kicad_mod` |

### DFM では出ていなかったが見つけた問題：受動部品のパッドの中のビア

- C56/C58/C60（22µF）、C59（10µF）の GND パッドと、C71（0402）の 3V3 パッドの中に、ビアの穴があった（穴の93〜100%）。はんだがビアに吸われ、C71 では部品が立つ不良（ツームストーン）の原因になる。
- 対応：すべて解消した（U1/U2 の EP 内のビアは意図どおりで対象外）。

### ビアの移動（`scripts/dfm_vias.py`、実測）

- パッドとの隙間が 0.1mm 未満、またはパッドにかかっていたビア36個のうち31個を動かした。つながる配線の端も一緒に動かす。隙間 0.15mm 以上（1個だけ 0.10mm 以上）。
- 動かせなかったもの：C70/C71.2 のビア（穴はパッドの外。ランドが接しているだけ）、C18.1 の ADC_1V9A ビア（隙間 0.05mm、同じネット、周りが混んでいる）。
- C71 は `scripts/dfm_fix2.py` で x を +0.4mm ずらして 3V3 ビアの穴をパッドの外に出した。C29 もコートヤードが重ならないよう +0.4mm。GND ビア (55.55, 36.3) → (55.55, 36.45)。

### 部品（発注画面の指摘）

- **L1〜L3**：C7413169（TDK VLS4012CX-2R2M-1）は EasyEDA にフットプリントがなく、JLC の配置画面に出なかった。→ **Taiyo Yuden NRS4018T2R2MDGJ（C92959）** に変更。2.2µH、Isat 3A、定格 2.2A、DCR 42mΩ、在庫 10,752。EasyEDA のランド（1.2×4.0mm、±1.4mm）は今のランド（1.3×4.0mm、±1.35mm）とほぼ同じで、フットプリントは変えていない。高さが 1.2→1.8mm になる。
- **C47/C54/C55/C57/C59**：同じ C15850 なのに値の表記（「10uF」「10uF 10V」）が違い、BOM の2行に分かれていた。JLC の画面ではこれが数量0・未選択になっていた。→ 値を「10uF 25V」にそろえて1行にした。C15850 の在庫は十分にある（API で確認）。
- **U1（TVP7002）**：在庫4個。発注画面の実装数が5枚になっていたため1個不足。**実装数を2枚にすれば足りる**（PCB を5枚作り、2枚だけ実装することもできる）。部品の変更はしていない。

### 修正（2026-09-30、利用者の指摘）C59 の GND 配線の切断と、ループの台形

- **不具合**：コミット 41883af の基板で、C59 の GND パッドとビアをつなぐ 0.6mm の配線が長さ0になり、パッドの角をかすめる 0.2mm の配線だけでつながっていた（DRC の未接続には出なかった）。原因は `dfm_vias.py` が、ビアの円の内側に両端がある 0.25mm の短い線まで、ビアと一緒に動かしたこと。
- **対策**（`dfm_vias.py`）：
  - 端がパッドの上にある短い線は動かさない。
  - ビアに接していた同じネットのパッドのうち、移動する配線でつながらないものには、パッドの中心から新しいビアまで、同じ太さの線を新しく引く。
  - ビアの内側だけに収まる極短の線は、長さ0にしてからテキスト編集で削除する（27本）。
  - ビアを動かす方向は、縦・横・45°を優先する。
- **台形**：ビアの移動で斜めになった 0.6mm の配線（レギュレータ周りのループ6か所と USB_VBUS の1か所）は、角の点をビアと同じ座標に動かして、直角に戻した（`dfm_fix2.py`）。
- **検査を追加**：`tools/padconn_cmp.py`。前後の基板で、各パッドに触れる配線の最大幅と、ビアとの接触を比べる。41883af では C59.2 だけが「0.6→0.2mm」と検出され、今回の基板では0件。
- 移動したビアは30個。動かせなかったのは C70/C71.2（ランドがパッドに接するだけ）、C18.1（隙間 0.05mm）、**U2.67/C34 の 3V3 ビア**（西は In2 の 1V2 の配線、ほかに空きがない。穴の縁から U2.67 まで 0.114mm、C34.1 まで銅どうしで 0.05mm。同じネットで蓋あり）。
- 検査（実測）：DRC エラー0・未接続0、未接続の比較 0→0、監査 PASS、回路図と基板は 570 ノード・値・フットプリント名とも一致、ERC は除外を適用して0件。製造データを出し直した（BOM・CPL の内容は変わらない）。

### 修正（2026-09-30、利用者の指摘）IC のピンとピンの間を通る配線

- JLC DFM の「Solder mask opening exposing trace」の危険1件（0.05mm）は、U1 のピン84/85（どちらも ADC_1V9PLL）の 0.2mm の隙間を、0.15mm の配線が通っている箇所だった。
- 同じ形（隣り合うピンの隙間を通る配線）を全 IC で調べると、U1 に11組、U3 に3組あった。いずれも同じネット（GND、ADC_1V9A、ADC_3V3A、ADC_1V9PLL）の隣のピンどうしを、ルーターが隙間を通してつないだもの。ほかに U5.5（3V3）の引き出しが U5.4 との隙間に入っていた（別のネットだがクリアランス 0.2mm は満たしていた）。短絡の恐れはないが、隙間のマスクが残らず、はんだ付けと検査の面で望ましくない。
- 対応：
  - `scripts/dfm_u1pll.py`：U1.85 をパッドの先端からまっすぐビア (27.8, 36.0) へ。
  - `scripts/dfm_gapfix.py`：隙間に入る区間52本と、消したことで浮いた切れ端18本を削除。孤立した12本のピン（U1.6/13/20/42/67/72/77/82/90/91/93、U3.26/40）を、隙間を通らない経路で同じネットの配線やビアへつなぎ直した（ルーター。隙間のマスを通行禁止にした。U1.72 だけは手で配線）。U5.5 の引き出しは曲がり点を動かし、パッドの内側の端から出るようにした。
- 検査（実測）：
  - IC のピンの隙間を通る配線：0本。
  - DRC：エラー0、未接続0。未接続の比較：0→0。
  - 監査：PASS。
  - 回路図と基板：570ノードで一致。
  - パッドの接続の比較（DFM 対応前の基板と比べて、細くなった・失われた接続）：0件。
  - シルク：置き直しは不要（0個）。
  - 製造データを出し直した。BOM・CPL の内容は変わらない。
